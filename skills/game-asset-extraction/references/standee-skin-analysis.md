# H 立绘识别：肤色占比分析（柚子社系 Gal，2026-08 Cafe Stella 实测）

立绘的 H 差分（裸体/大面积暴露）文件名无任何标记，sinfo 的 dress 衣装行有「裸」「裸私服」等 R18 衣装名，但衣装→tlg 文件的映射在加密 pbd（TJS/4s0 字节码）里。**肤色像素占比启发式可以绕开 pbd 直接识别**——裸体立绘的皮肤暴露面积显著高于穿衣立绘。

## 判定参数（实测调优）

```
肤色判定（对不透明像素，RGBA）：
  R>90 且 G>35 且 B>15 且 R>G 且 G>=B 且 (R-B)>20 且 (max(R,G,B)-min(R,G,B))>20
肤色占比 = 肤色像素数 / 不透明像素数
```

- **>= 60%**：H 高置信（裸体/大面积暴露）——Cafe Stella 全量 1811 张出 67 张候选
- **45-60%**：疑似（泳装/浅色衣装/半裸），单独列表待人工确认
- **< 45%**：普通穿衣立绘

## 关键过滤（防误报）

1. **只统计完整立绘尺寸**（高度 >= 1400px）：腕/肢体差分碎片肤色占比 100%（比如"裸腕差分"），必须排除。判定尺寸用 `PIL.Image.open(p).size`，先开图取尺寸再算肤色。
2. **不透明像素数下限**（>= 30000）：排除表情/装饰小碎片（149x120 等）。
3. **标准版与 2x 高清成对**：`角色a_0_编号.png`（508x1725）和 `角色a_编号.png`（1686x3538 = 2 倍）是同一姿态两种分辨率，两者肤色占比几乎相同——提取时成对收录，或用清单让用户抽查。
4. 浅色衣服（白色/米色连衣裙）可能被误判进 45-60% 段，需人工抽查确认。

## 立绘文件命名规律（Cafe Stella 实测）

- `角色a_0_编号.png`：完整立绘标准版（508x1725 / 843x1769），脸区不透明率 ~99.6%（自带表情，可直接用，不需要合成）
- `角色a_编号.png`：同姿态 2x 高清版（1686x3538 等），可直接作高清源
- 小图（149x120 等）：表情/装饰碎片
- 每个角色标准版完整立绘只有 12-27 张（252/1811 总量），其余是高清版和碎片

## sinfo / pbd（立绘分层配置）

- `.sinfo` **必须 UTF-16LE 解码**（utf-8 读会因 \u0000 使 `face` 行匹配不到）；dress 行 = 衣装列表（裸/裸私服/メイド服/私服/チャイナ服...），face 行 = 表情 id 列表
- `.pbd` = 加密 TJS 字节码（TJS/4s0 魔数），内容高熵乱码，静态解析不到衣装→tlg 映射；要表情差分替换合成需运行时提取（KrkrDump 注入游戏）
- 结论：解包出的立绘 PNG 已是完整立绘（含基本表情），普通二创直接用即可；"分层合成"是表情替换的进阶功能

## 执行脚本骨架

```python
from PIL import Image
import numpy as np

def skin_ratio(path):
    img = Image.open(path).convert('RGBA')
    arr = np.array(img)
    a = arr[..., 3]
    rgb = arr[..., :3].astype(int)
    mask = a > 100
    if mask.sum() < 30000:          # 排除小碎片
        return None, img.size
    r, g, b = rgb[..., 0][mask], rgb[..., 1][mask], rgb[..., 2][mask]
    mx = np.maximum(np.maximum(r, g), b)
    mn = np.minimum(np.minimum(r, g), b)
    skin = (r > 90) & (g > 35) & (b > 15) & (r > g) & (g >= b) & ((r - b) > 20) & ((mx - mn) > 20)
    return skin.sum() / mask.sum(), img.size
# 全量：遍历 fgimage/角色目录，size[1]>=1400 且 sr>=0.60 → H 候选
# 产出：复制到 R18/03_H立绘/ + _H立绘清单.txt（标注肤色占比和尺寸）
```
